Teachable Machine

Treine um modelo de IA que reconhece imagens, sons ou poses corporais — direto no navegador, sem escrever uma linha de código. Em poucos minutos você tem um classificador funcionando.

1. Visão geral

Teachable Machine é uma ferramenta gratuita do Google que permite treinar modelos de classificação sem programar. Você mostra exemplos para o computador, ele aprende a diferenciá-los e pronto: tem um modelo que classifica entradas novas em tempo real.

É um exemplo prático de aprendizado supervisionado: você ensina por exemplos. Se quiser que o modelo distinga "cachorro" de "gato", você dá várias fotos rotuladas como cachorro e várias rotuladas como gato. O modelo aprende os padrões e generaliza.

No contexto do hackathon
Teachable Machine é a ferramenta certa quando o coração do produto é "identificar algo automaticamente": um lixo, um gesto, uma palavra falada, uma postura. Não substitui o app — geralmente você combina o modelo com uma tela em outra ferramenta (Lovable) ou apresenta o modelo rodando em uma página do próprio Teachable Machine.

O que é (e o que não é)

  • É: uma ferramenta para criar classificadores que rodam no navegador.
  • Não é: um app pronto para o usuário final — você ainda precisa de uma interface.
  • É: gratuito e sem cadastro obrigatório (você só precisa de conta Google se quiser salvar projetos no Drive).
  • Não é: um modelo de geração de imagens, texto ou áudio. Só classificação.

2. Quando usar (e quando não)

✓ Use Teachable Machine quando…

  • O produto precisa identificar algo visual, sonoro ou postural
  • Você consegue coletar exemplos rotulados em poucos minutos
  • As classes são visualmente/auditivamente distintas entre si
  • Demo ao vivo com webcam ou microfone faz sentido para o seu pitch

✗ Não use Teachable Machine se…

  • Seu produto é só uma tela com lógica → use Lovable
  • Você precisa que o modelo gere algo (texto, imagem) → use APIs de IA generativa via Lovable
  • As classes são quase iguais (ex: distinguir 50 espécies de cogumelo) — Teachable Machine não tem capacidade pra isso
  • Você precisa de altíssima precisão (decisão médica, segurança crítica) — para isso, modelos profissionais
Combinação poderosa
Teachable Machine + Lovable funciona muito bem: você treina o modelo, exporta como TensorFlow.js e pede no Lovable para hospedar uma tela que use o modelo. Aí o usuário tem app e IA juntos. É um caminho mais avançado — só vá por ele se o squad estiver confortável.

3. Os 3 tipos de projeto

Quando você abre o Teachable Machine, ele pergunta qual tipo de projeto criar. Escolha de acordo com o sentido que seu produto vai usar.

📷 Image

Classifica imagens estáticas ou frames de webcam. O mais usado e versátil. Bom para: tipo de objeto, expressão facial, gesto com a mão, postura geral, classificar lixo, identificar planta.

🎤 Audio

Classifica sons curtos (~1 segundo). Útil para: palavras-chave faladas, sons de animais, alarmes, instrumentos musicais, palmas vs assobios. Sempre exige um background "ruído ambiente" como classe de calibração.

🤸 Pose

Classifica posturas corporais usando os pontos-chave do esqueleto (ombros, cotovelos, joelhos, etc.). Ideal para: exercícios físicos, postura ergonômica, jogos baseados em movimento, libras simples.

Não dá pra misturar
Cada projeto trabalha com um único tipo de entrada. Se seu produto precisa entender imagem E som ao mesmo tempo, são dois modelos separados — e juntar isso costuma ser mais complexo do que cabe em um hackathon.

4. Antes de começar

Acesso

Acesse teachablemachine.withgoogle.com e clique em "Get Started". Não precisa criar conta — só se quiser salvar o projeto na nuvem (Google Drive), aí entre com Google.

O que ter em mãos

  • Um computador com webcam (para Image e Pose) ou microfone (para Audio)
  • Lista de 2 a 8 classes que você quer distinguir (mais que isso vira ruim)
  • Pelo menos 30 exemplos por classe em mente — tempo, fontes, fundos diferentes
  • Um nome para o projeto e ideia de onde vai usar (link, embed, tela em outro app)

Navegador

Funciona melhor em Chrome, Edge ou Firefox atualizados. Safari às vezes dá problema com webcam/microfone. Tudo roda no navegador — seus dados não saem do computador (privacidade preservada).

5. Fluxo geral em 4 etapas

Independente do tipo de projeto, a lógica é a mesma:

  1. Definir as classes Você cria caixas, uma para cada coisa que quer distinguir. Dê nomes claros (em vez de "Class 1", coloque "Lixo orgânico", "Plástico", "Metal"). Pode adicionar quantas quiser, mas mantenha entre 2 e 8 para resultados bons.
  2. Coletar exemplos Para cada classe, você grava (webcam/microfone) ou faz upload de exemplos. Quanto mais exemplos variados, melhor o modelo. Mínimo prático: 30-50 por classe.
  3. Treinar Clique em "Train Model". O treinamento acontece no seu próprio navegador (não envia dados para servidor). Leva de poucos segundos a 1-2 minutos dependendo do volume.
  4. Testar e exportar Antes de exportar, teste o modelo na seção "Preview" ao lado. Se estiver bom, clique em "Export Model" e escolha o formato (TensorFlow.js para web é o mais comum).
Itere rápido
Você pode retreinar quantas vezes quiser. Adicione mais exemplos, retreine, teste, repita. Cada ciclo leva poucos minutos. Não tente acertar na primeira — o ciclo de melhorar está na essência.

6. Image Project (passo a passo)

É o tipo mais usado. Aqui o passo a passo detalhado.

Passo 1 — Criar o projeto

Na tela inicial: New Project → Image Project → Standard image model. (A opção "Embedded" é para microcontroladores e provavelmente não cabe no hackathon.)

Passo 2 — Configurar as classes

  1. Renomeie "Class 1" e "Class 2" com nomes descritivos clicando no ícone de lápis.
  2. Adicione mais classes com o botão "Add a class" se precisar.
  3. Recomendação: mantenha 2 a 6 classes. Mais que isso aumenta muito o tempo de coleta e a chance de erro.

Passo 3 — Coletar imagens

Para cada classe, você tem duas opções:

  • Webcam — clica e segura "Hold to Record" para gravar várias imagens rapidamente. O Teachable Machine captura múltiplos frames por segundo.
  • Upload — arraste arquivos do computador, ou faça upload de uma pasta inteira de uma vez.

Quantas imagens coletar?

QuantidadeResultado esperado
Menos de 20Funciona apenas em condições idênticas às do treino
30 a 50Funciona razoavelmente. Mínimo aceitável.
80 a 150Funciona bem em variações moderadas. Sweet spot do hackathon.
200+Funciona muito bem. Limite prático para tempo de hackathon.

Variar é mais importante que quantidade

Para cada classe, varie:

  • Ângulo — frente, lados, leve inclinação
  • Distância — mais perto, mais longe da câmera
  • Iluminação — luz do dia, luz artificial, mais escuro
  • Fundo — diferente em cada bloco de imagens
  • Pessoas/objetos diferentes — se aplicável
Erro comum: fundo viciado
Se todas as suas imagens da classe "maçã" têm a mesma mesa branca de fundo, o modelo aprende que "mesa branca = maçã". Quando você testar com fundo diferente, ele erra. Sempre varie o fundo ou use a classe "background"/"vazio" como referência.

Passo 4 — Treinar

  1. Clique em "Train Model".
  2. Não troque de aba do navegador durante o treino — pode pausar.
  3. Leva ~30 segundos a 2 minutos. Aparece uma barra de progresso.

Passo 5 — Testar no Preview

Logo ao lado do botão de treino, aparece o Preview. Ele mostra a webcam em tempo real e o que o modelo está prevendo, com porcentagem de confiança. Mostre objetos das suas classes para ver se acerta.

Teste especialmente com:

  • Variações que você NÃO usou no treino (fundo novo, iluminação diferente)
  • Casos limítrofes — coisas que poderiam ser confundidas
  • Coisas que não são nenhuma classe — para ver o quão "confiante" o modelo fica em algo que não conhece
Treinou mas não está bom?
Não retreine do zero. Volte para a coleta, adicione mais exemplos das classes problemáticas (especialmente nos casos onde está errando) e clique em Train Model novamente. O modelo aprende rápido com correções direcionadas.

7. Audio Project

Para classificar sons curtos. Tem uma particularidade: sempre começa com uma classe obrigatória chamada "Background Noise".

Background Noise é obrigatório

Antes de treinar suas classes, você precisa gravar pelo menos 20 segundos de "silêncio" (o som ambiente do lugar onde o modelo vai rodar). Isso é a calibração: o modelo precisa saber o que é "nada acontecendo" para distinguir de algo acontecendo.

Se o seu projeto vai rodar em sala de aula, grave o som da sala vazia. Se em casa, grave o som da casa. Sons ambientes diferentes confundem o modelo.

Coletando classes

  • Cada classe precisa de pelo menos 8 amostras de ~1 segundo cada. Funciona melhor com 20+ amostras.
  • Sons curtos e distintos funcionam muito melhor que palavras longas ou frases.
  • Bons exemplos: "ai!", palmas, assobio, miado, "abre", "fecha", "liga", "desliga".
  • Maus exemplos: frases longas, músicas inteiras, sons muito parecidos entre si.

Dicas específicas

  • Grave sempre na mesma distância do microfone que o usuário final vai usar.
  • Varie ligeiramente: tom de voz, intensidade, sotaque (se mais de uma pessoa for usar).
  • Em ambiente barulhento, grave o ruído de fundo daquele ambiente como background.
Boa aplicação no hackathon
Audio Project funciona bem como "controle por voz simples": o usuário fala uma palavra-chave e o app reage. Mais simples que um assistente de verdade, mas suficiente para uma demo no Demo Day.

8. Pose Project

Reconhece posturas corporais. Em vez de olhar pixels, usa os pontos-chave do esqueleto (cabeça, ombros, cotovelos, pulsos, quadril, joelhos, tornozelos).

Por que isso é uma vantagem

Como ele trabalha com pontos do esqueleto e não com a imagem direta, o modelo é menos sensível a:

  • Cor da roupa
  • Iluminação
  • Fundo da cena

Em compensação, exige que a pessoa esteja com o corpo bem visível para a câmera (preferencialmente da cabeça aos joelhos).

Quantas amostras coletar

  • Mínimo: 50 amostras por classe.
  • Idealmente: 100-200 amostras por classe, com pessoas diferentes se possível.

Boas aplicações

  • Detector de postura (boa/ruim ao estudar)
  • Contador de exercícios (agachamento, polichinelo)
  • Jogos baseados em movimento
  • Reconhecimento de sinais simples (mãos para cima, mãos abertas, parado)
Limitação
Pose Project trabalha melhor com uma pessoa por vez no quadro. Se houver várias pessoas, o desempenho cai bastante.

9. Qualidade do modelo

Como saber se seu modelo está bom o suficiente para o Demo Day? E como melhorar quando não está?

Sinais de modelo bom

  • No Preview, a classe correta aparece com confiança acima de 80% na maioria dos testes.
  • Quando você mostra algo fora das classes, a confiança fica espalhada (40/30/30) em vez de 95% em uma errada.
  • Funciona em condições ligeiramente diferentes do treino (luz, fundo, ângulo).
  • Confunde casos esperados (objetos parecidos), não casos óbvios.

Sinais de modelo ruim e como consertar

SintomaCausa provávelO que fazer
Acerta no treino, erra em qualquer variação Falta de variedade nos exemplos Adicione exemplos com fundos, ângulos e iluminação diferentes
Sempre prevê a mesma classe Desbalanço (uma classe tem muito mais exemplos) Iguale o número de exemplos entre classes
Confunde duas classes específicas Classes muito parecidas ou exemplos sobrepostos Refaça os exemplos das duas classes problemáticas garantindo distinção visual clara
Confiança nunca passa de 60% Poucos exemplos no geral Aumente o volume — mire em 100+ por classe
Funcionou no Preview mas não no app exportado Iluminação/câmera diferente Re-treine com exemplos coletados na câmera/ambiente onde o app vai rodar

Configurações avançadas (opcional)

Em "Advanced", você pode ajustar:

  • Epochs — quantas vezes o modelo vê todos os exemplos. Padrão é 50. Subir pode melhorar precisão, mas demora mais e pode "viciar" no treino.
  • Batch size — quantos exemplos processa por vez. Padrão geralmente está bom.
  • Learning rate — quão rápido o modelo aprende. Mexer aqui é avançado; só mude se souber o que está fazendo.

Para o hackathon, os valores padrão funcionam bem em quase todos os casos. Foque em coletar bons exemplos antes de mexer aqui.

10. Exportando o modelo

Treinou e está bom? Hora de exportar para usar fora do Teachable Machine.

Os 3 formatos de exportação

FormatoQuando usar
TensorFlow.jsPara usar em app web (Lovable, qualquer site). Mais comum no hackathon.
TensorFlowPara usar em Python. Útil em scripts ou backend pesado. Raro no hackathon.
TensorFlow LitePara usar em celular ou microcontrolador. Útil se for embarcar em um device físico.

Caminho rápido: Hosted Model

O caminho mais fácil é o Upload my model dentro de TensorFlow.js. O Teachable Machine hospeda gratuitamente e te dá uma URL pública assim:

https://teachablemachine.withgoogle.com/models/AbCdEfGh1/

Essa URL é tudo que você precisa para usar o modelo em qualquer lugar. Guarde-a com carinho.

Caminho alternativo: Download

Se preferir ter os arquivos localmente (e não depender de internet), clique em Download my model e baixa um ZIP com 3 arquivos:

  • model.json — a "receita" do modelo
  • metadata.json — informação sobre as classes
  • weights.bin — os "pesos" (o que o modelo aprendeu)

Você precisa hospedar esses 3 juntos em algum lugar acessível por URL. Para o hackathon, o caminho hospedado é mais prático.

Dica de demo
Mesmo se você não conseguir integrar com Lovable a tempo, o Teachable Machine te dá uma página de teste pública via "Get the shareable link" no menu de exportação. Você pode mostrar essa página ao vivo no Demo Day. Não fica tão polido quanto um app, mas funciona.

11. Integrando com Lovable

Caminho para combinar Teachable Machine + Lovable em um único produto. Avançado, mas viável em hackathon se o squad estiver confortável.

O que você precisa antes de tudo

  • O modelo treinado e hospedado, com a URL em mãos (ex: https://teachablemachine.withgoogle.com/models/AbCdEf/)
  • Um projeto Lovable iniciado

Prompt para o Lovable

Seguindo o padrão Contexto + Objetivo + Restrições:

Quero adicionar uma tela ao app que use a câmera do navegador
para reconhecer [O QUE]. O modelo já está treinado no
Teachable Machine e fica nesta URL:

https://teachablemachine.withgoogle.com/models/[ID]/

Use a biblioteca tmImage do Teachable Machine para carregar
o modelo, abra a webcam, mostre as previsões em tempo real
abaixo da câmera com a porcentagem de confiança.

Quando a confiança da classe "[CLASSE_ALVO]" passar de 85%,
exibe a mensagem "[MENSAGEM]" e [O QUE FAZER].

Adiciona um botão "Parar câmera" para liberar a webcam.

O Lovable conhece a biblioteca tmImage e consegue gerar o código integrando. Pode ser preciso uma ou duas iterações para ajustar.

Permissão de câmera
O navegador vai pedir permissão para acessar a webcam quando o usuário entrar na tela. Garanta que o app explica isso claramente — se não, o usuário nega e o modelo não funciona.

12. Cenários comuns no hackathon

Cenário A — Identificador de descarte correto

O usuário aponta a câmera para um item, o app diz se é orgânico, plástico, papel, metal, eletrônico ou pilha.

  • Tipo: Image Project
  • Classes: 4-6 (orgânico, plástico, papel, metal, e-lixo, pilha)
  • Coleta: 80-120 fotos por classe, com objetos reais variados
  • Demo Day: apresenta a câmera reconhecendo objetos que você trouxe

Cenário B — Acessibilidade por gestos

App de comunicação para pessoas com dificuldade de fala: o usuário faz um gesto e o app fala uma frase.

  • Tipo: Pose Project ou Image Project
  • Classes: 4-6 gestos distintos (mãos para cima, mão fechada, mão aberta, ok, etc.)
  • Coleta: 100+ amostras por gesto, com pessoas diferentes
  • Demo Day: apresenta os gestos sendo reconhecidos e gerando frases

Cenário C — Coach de postura

App que avisa quando o usuário está com postura ruim ao estudar.

  • Tipo: Pose Project
  • Classes: 2-3 (boa postura, postura curvada, ausente)
  • Coleta: 200 amostras por classe, várias pessoas
  • Demo Day: webcam ao vivo durante o pitch, com alerta quando detectar postura ruim

Cenário D — Comando de voz simples

Controle de algo (luz, página, jogo) por palavras-chave.

  • Tipo: Audio Project
  • Classes: Background + 3-5 comandos curtos
  • Coleta: 30+ amostras por comando, com 2-3 pessoas falando
  • Demo Day: demo ao vivo dando comandos

Cenário E — Identificador de espécies/itens didáticos

App educativo: aponta a câmera para [planta/animal/objeto] e ele te ensina sobre.

  • Tipo: Image Project
  • Classes: 3-6 itens bem distintos entre si
  • Coleta: imagens variadas (Google Imagens funciona como ponto de partida)
  • Combinação: exporta para Lovable, que mostra a info detalhada da classe identificada

13. Resolvendo problemas

A webcam não aparece / "Permissão negada"
Solução: Clique no ícone de cadeado (à esquerda da URL no navegador) e habilite a câmera. Recarregue a página. Confirme que o navegador é Chrome, Edge ou Firefox.
Treinei mas o modelo prevê sempre a mesma classe
Solução: Provavelmente uma classe tem muito mais exemplos que as outras. Conte: tente igualar a quantidade. Se uma classe estiver muito acima (ex: 200 vs 30), apague exemplos da maior ou colete mais nas menores até ficarem balanceadas.
Acerta no laboratório mas erra na sala de aula
Solução: O modelo aprendeu padrões do ambiente do treino (iluminação, fundo). Colete mais exemplos no ambiente onde vai rodar e retreine. Variar exemplos de propósito é a chave.
Pose Project não está reconhecendo o esqueleto
Solução: Posicione a webcam de modo que todo o corpo (cabeça aos joelhos) apareça. Roupa muito larga e fundo bagunçado atrapalham. Ilumine bem o ambiente.
Audio Project tem alta confiança no Background Noise mesmo quando falo
Solução: O microfone pode estar com volume baixo, ou o background tem muito ruído parecido com a sua voz. Aproxime a boca do microfone e regrave o background no mesmo ambiente em silêncio real.
"Train Model" travou no meio
Solução: Você provavelmente trocou de aba durante o treino. Mantenha a aba ativa e tente novamente. Se persistir, recarregue a página (suas amostras ficam salvas se você estiver logado e com auto-save) ou reduza a quantidade de classes/exemplos.
Adicionei mais exemplos mas o modelo não melhorou
Solução: Lembre de clicar em Train Model novamente. Adicionar exemplos sem retreinar não muda nada. Verifique também se os novos exemplos estão na classe certa.
Perdi todo o trabalho ao fechar a aba
Solução: O Teachable Machine não salva automaticamente — entre com Google e use "Save project to Drive". Faça isso a cada milestone. Como alternativa, "Download project as file" baixa um arquivo .tm que você pode reabrir depois.
O modelo exportado não funciona no Lovable
Solução: Confira que (1) você usou TensorFlow.js, (2) escolheu "Upload my model" para hospedar, (3) está usando a URL completa hospedada (não os arquivos baixados sem hospedagem), e (4) testou a URL em {URL}/metadata.json direto no navegador — se voltar JSON, está funcionando. Mostre a URL e o erro para o Lovable em Chat Mode antes de gastar créditos em uma geração.
A confiança fica oscilando muito (70% / 30% / 70% / 30%)
Solução: Modelo está em dúvida entre duas classes. Adicione exemplos das duas classes mostrando claramente a diferença, e considere se elas são realmente distinguíveis ou se é um caso onde o modelo nunca vai conseguir separar bem.

14. Ética e limitações

Trabalhar com IA, mesmo no hackathon, vem com responsabilidades. A banca tende a valorizar squads que demonstram consciência sobre isso.

Vieses são inevitáveis se você não tomar cuidado

Se todos os exemplos da sua classe "rosto feliz" forem de pessoas brancas e jovens, o modelo vai funcionar pior em pessoas de outras etnias e idades. Isso não é "culpa do modelo" — é da escolha de exemplos.

Sempre que o produto envolver reconhecimento de pessoas:

  • Use exemplos diversos (etnia, idade, gênero, características físicas)
  • Teste explicitamente com pessoas que não estavam no treino
  • Mencione no pitch as limitações conhecidas e como abordaria isso em um produto real

Privacidade dos exemplos

Se você gravou colegas no treinamento, pergunte se eles autorizam o uso. Para o Demo Day, considere usar apenas membros do squad nos exemplos, ou objetos em vez de pessoas.

O que o modelo NÃO sabe

Teachable Machine não "entende" o que é uma maçã — ele só sabe que pixels com certo padrão se parecem com os exemplos que você rotulou de "maçã". Isso significa que:

  • Pode confundir uma foto de maçã na tela com uma maçã real
  • Pode falhar em maçãs muito diferentes das do treino (verdes, mordidas, partidas)
  • Não generaliza para conceitos que você não ensinou

Saber comunicar essas limitações no pitch demonstra maturidade — a banca aprecia.
